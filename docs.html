ANATOMY OF AN IN-GAME FRAME

  1. clear
  2. world scenery — floor tiles + walls (the STATIC cache), placed props, elevators. With ?pixel=N all of it rasterizes inside the world-anchored art-res group and composites as one sub-pixel quad under the camera sway (roll + drift applied to the finished image).
  3. actors — corpses, then ground weapons, then standing robots + boss + bullets: baked/live pixel sprites on quads that move smoothly at native resolution, never snapped to the world grid.
  4. HUD + comms — health, objective, dialogue letterbox, rocking portraits: crisp, outside any group.
  5. TV-static grain quad (?noise=0 removes it).
  6. POSTFX pass, if any (pause modal wash, kill blur-out, warp trails…).

THE COST MODEL

  • Bandwidth is the enemy at Retina: every full-screen layer reads (+ writes) ~4.5M physical pixels. MSAA (~4x per layer) measured 30 fps on the 2018 MacBook and was removed; the grain quad — the cheapest possible overlay — still pays one read + write.
  • The command stream is the CPU contract: one crossing per frame; the STATIC cache turns a floor's ~2000 re-recorded floats into 2.
  • Art-res rasterization is a fill win: pixel groups and the DRIVE shader compute at art resolution and pay native resolution only for one upscaled quad — the crunch and the savings come from the same place.
  • Aliasing is the art direction (CLAUDE.md ## Design): hard stair-stepped edges everywhere; smoothness lives only in motion.
